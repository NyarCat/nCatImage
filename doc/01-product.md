# 01. 제품 목표와 범위

이 문서는 목표 기능표다. 현재 Linux 개발판의 부분 구현/미구현 여부는 [08 구현 상태](08-implementation-status.md)를 따른다.

v0.4.3 · 2026-11-16 갱신. AI 코딩 에이전트 기반 개발이며 버전별 변경은 [작업 내역](../CHANGELOG.md)에 기록한다.

## 1. 한 가지 목적

폴더 또는 압축파일을 열어 만화를 끝까지 **빠르게, 끊김 없이, 적은 메모리로** 읽는다. 사진 편집·관리·AI·소설/전자책 플랫폼이 아니다. 제품명은 저장소명에 맞춰 `nCatImage`를 사용한다.

| 사용자 상황 | 기대 동작 |
|---|---|
| ZIP/CBR 만화 열기 | 전체 해제 없이 첫 페이지 표시, 자연순 탐색 |
| 수천 장 넘기기 | 입력 즉시 선택 갱신, 최신 페이지만 반영 |
| 좌→우/우→좌 만화 읽기 | 단일/두 장·표지·물리 페이지 순서를 명확히 분리 |
| 고해상도/긴 이미지 | 화면에 필요한 해상도로 읽고 확대 시 갱신 |
| 메모리 작은 기기 | prefetch/cache를 먼저 줄이고 읽기 상태 유지 |
| NAS·네트워크 폴더 읽기 | OS가 연결한 SMB/FTP/SFTP를 기존 읽기 경로로 전달, 인증/장애 안내 |
| 재실행 후 이어 읽기 | 허용한 경우 정확한 항목/읽기 모드 복원 |

현재 제품 검증은 Linux x64이며 Android 앱은 만들지 않는다. Windows 꿀뷰와 Android 리더의 읽기 흐름은 참고하되 OS별 외형 복제는 목표가 아니다.

## 2. 기능 우선순위

| ID | 단계 | 기능 | 완료 기준 |
|---|---|---|---|
| R01 | P0 | 파일/폴더/압축 열기 | 명령행·대화상자·드롭·desktop 연결, 지원/오류 안내 |
| R02 | P0 | 페이지 탐색 | 자연 정렬/역순·첫/끝/이전/다음·번호 이동·파일명 검색·수동 새로고침 |
| R03 | P0 | 읽기 모드 | 한 장/두 장·표지 단독·좌우 방향·가로 페이지 단독 |
| R04 | P0 | 표시/확대 | 전체/폭/높이/1:1·포인터 줌·패닝·작은 이미지 확대 옵션 |
| R05 | P0 | 기본 형식/압축 | 04의 P0 matrix를 Linux 배포본에서 통과 |
| R06 | P0 | 읽기 전용 조작 | 임시 화면 회전, 원본 파일 bytes 불변 |
| R07 | P0 | 최소 화면 | 전체 화면·자동 숨김 도구·페이지 번호·지연 thumbnail strip |
| R08 | P0 | 읽기 기록 | opt-in 이어보기·최근 책·개별/전체 삭제·기록 없이 열기 |
| R09 | P0 | 자원/복구 | bytes 예산·최신 선택·취소·worker 장애/timeout·정리 |
| R10 | P0 | 기본 접근성 | 표준 Tab/Enter·한글 IME·도움말·Orca 핵심 읽기 |
| R11 | P1 | 추가 형식/압축 | AVIF/JXL/TIFF/QOI/TGA·7Z/CB7·TAR/CBT, 04의 검증 범위 |
| R12 | P1 | 펼침 분할 | 한 가로 이미지를 읽기 방향에 맞는 가상 반쪽 페이지로 보기 |
| R13 | P1 | 세로 연속 보기 | 표시 영역 주변만 decode/보관·위치 anchor 유지 |
| R14 | P1 | 책 단위 편의 | 북마크·같은 폴더 이전/다음 책·기본 단축키 재매핑 |
| R15 | P1 | 마무리 | 전체 UX/접근성·설정 migration·Linux 설치/업데이트/제거 |
| R16 | P2 | 선택적 추가 형식 | HEIF/HEIC·JPEG2000·PSD 합성 이미지·선택 RAW 등 개별 검증 |
| R17 | P2 | 선택적 움직임 | GIF/WebP/APNG 재생·일시정지, 사용자가 켤 때만 worker/프레임 예산 확장 |

배포된 0.4.3의 GIF/WebP는 첫 합성 프레임 정지 표시다. 후속 사용자 요청으로 미릴리스 소스는 GIF/AGIF·WebP·APNG 순차 자동 재생을 추가했다. R17의 일시정지·선택적 활성화 UI·재생 제어 전체가 완료된 것은 아니다. P1 TIFF의 내부 페이지는 별도 읽기 페이지로 노출한다. 상세 matrix는 04가 기준이다.

## 3. 의도적으로 넣지 않을 기능

- 자르기·크기 변경 저장·밝기/대비/선명도 필터·색 편집·주석·내보내기·형식 변환·원본 덮어쓰기.
- 일반적인 파일 복사/이동/삭제·이름 변경·휴지통 관리는 범위 밖이다. 단, 원본 위치 열기/경로 복사와 `Del`로 현재 일반 이미지 한 장을 OS 휴지통으로 보내는 명시적 조작은 지원한다. 압축 파일의 내용을 편집하지 않는다.
- 사진 라이브러리 DB·전체 디스크 스캔·표지 자동 수집·태그/평점·중복 검출.
- 자체 클라우드·FTP/SMB/SFTP 프로토콜 클라이언트·OPDS·다운로드/계정 관리자·앱 내 AI 기능·원격 분석. 사용자 요청으로 OS의 KIOFuse/GVfs/FUSE를 통한 네트워크 읽기는 포함한다. AI를 개발에 활용하는 것과 앱에 AI 기능을 넣는 것은 구분한다.
- 영상·PDF·SVG·EPUB·텍스트 소설·HDR 모니터 출력·중첩 아카이브 자동 읽기.
- 화려한 페이지 넘김 효과·상시 배경 애니메이션·원본 전량 predecode·전체 아카이브 자동 추출.

자동 페이지 넘김/슬라이드쇼는 코믹뷰어의 기본 요구가 아니므로 1.0 범위에 넣지 않는다. 터치용 전체 OS 앱이나 모든 rare 코덱 지원도 미리 약속하지 않는다.

## 4. 품질 우선 규칙

- 정상적인 기본 만화 corpus는 기본 메모리 모드에서 오류 없이 읽어야 한다. 제한을 낮춰 실패율을 늘린 것을 최적화라 부르지 않는다.
- 모든 고해상도 포맷을 작은 RAM으로 1:1 표시할 수 있다고 약속하지 않는다. 안전한 축소가 없으면 비용/대안을 안내한다.
- 오류/느린 페이지는 탐색을 막지 않는다. 한 페이지 실패로 책 전체를 제거하지 않는다.
- 읽기 기본은 원본 비파괴·로컬 오프라인·기록 비활성이다. 네트워크 읽기 때만 사용자가 지정한 서버에 OS 도구로 연결한다. 기능 확장보다 대기시간/메모리/읽기 동작 회귀를 먼저 해결한다.
- 05/07의 수치는 검증할 초기 목표다. Rust라는 언어 선택 자체가 가벼움의 증거는 아니다.

## 5. 참고 방향의 채택/제외

| 참고 | 채택 방향 | 제외 |
|---|---|---|
| 꿀뷰 | 빠른 파일 열기·압축 내부 감상·키/휠·간결한 overlay | 변환·편집·독점 자산·내부 구현 추정 |
| Android 코믹 리더 공통 패턴 | 읽기 방향·탭 영역·화면 숨김·표지/두 장·이어보기 | 모바일 OS 전용 서비스·광고·서재 인덱싱·특정 앱 기능 단정 |

특정 Android 앱의 store 링크/버전이 제공되면 실제 화면/공개 문서와 비교해 02를 보완한다. 그 전에도 일반적인 읽기 명세로 개발 가능한 수준을 유지한다.

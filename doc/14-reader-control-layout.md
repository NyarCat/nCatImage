# 14. 읽기 조작과 제목 표시줄

GTK4와 Win32가 같은 위치 규칙을 사용한다. 세 조작부는 서리 유리 오버레이이며 표시 여부가 이미지 크기나 배율에 영향을 주지 않는다.

| 위치 | 조작 |
|---|---|
| 상단 중앙 | 이전·다음 페이지, 페이지 번호 입력 후 `Enter` 또는 오른쪽 `▾`로 이동, 읽기 방향, 상단 고정 |
| 왼쪽 아래 | 이전·다음 프레임, 재생/일시정지 버튼, 배속, 프레임 번호 이동. 현재 이미지가 애니메이션일 때만 표시 |
| 오른쪽 아래 | 현재 배율과 잘리기 전 표시 크기(픽셀), 확대·축소·맞춤·회전·전체 화면, 하단 고정. 배율 표시는 확대·축소 버튼 왼쪽에 배치 |

상단 고정은 상단에만, 하단 고정은 아래쪽 두 조작부에 적용된다. 고정하지 않은 조작부는 가장자리로 마우스를 옮기면 나타난다. 백틱은 상·하단 고정을 함께 전환한다.

- 이미지 영역 우클릭(또는 `Shift+F10`/메뉴 키)으로 **파일 열기**, **폴더 열기**, **주소 열기**를 선택한다. 주소는 별도 입력 대화상자에서 열며 `Ctrl+L`도 같은 대화상자를 호출한다. 파일·폴더의 기존 단축키와 드롭은 유지한다.
- 제목 표시줄에는 페이지 번호·파일명과 상태/안내(이미지 형식·해상도, 로딩, 오류 등)를 표시한다. 애니메이션일 때는 별도로 `프레임 현재/전체`를 붙이며 전체 수가 아직 확인되지 않으면 `?`를 표시한다. 이 창 제목은 시스템 타이틀바가 없는 전체 화면에서 화면에 보이지 않는다.
- 뷰어에서 `Del`을 누르면 현재 일반 이미지 파일을 **삭제하시겠습니까?** 확인 뒤 OS 휴지통으로 보낸다. **다시 묻지 않기**는 삭제를 확인했을 때 현재 앱 실행 동안만 적용한다. 삭제 후에는 다음 이미지(없으면 이전)를 열며, 이미지가 더 없으면 뷰어를 비운다. ZIP/CBZ 내부 이미지는 **압축 파일이라 삭제 불가능합니다** 경고만 표시한다. 휴지통 사용에 실패해도 영구 삭제하지 않는다.
- GTK와 Win32 모두 새 페이지가 준비될 때까지 기존 이미지를 유지하고 추가 페이지 이동 입력은 무시한다. 읽기에 실패하면 자동으로 건너뛰지 않고 오류를 표시하며, 그다음 입력으로 이전·다음 페이지에 갈 수 있다.
- 재생 상태를 별도 텍스트로 반복 표시하지 않는다. 같은 버튼이 재생 중에는 `Ⅱ`, 일시정지·종료 상태에서는 `▶`로 표시된다. 배속과 프레임 단위 이동은 유지한다.
- 오른쪽 위 `ⓘ`는 상단 조작부의 고정·자동 표시 규칙을 따르며 상단 UI와 함께 숨겨진다. 이미 열린 메타데이터는 유지되며, 버튼이 숨겨져도 `Tab`/`Shift+Tab`으로 토글할 수 있다. 패널 상단의 겹친 문서 아이콘을 누르면 현재 메타데이터 전체를 일반 텍스트로 클립보드에 복사한다.
- Windows에서 창 가장자리를 드래그하는 동안 조작 버튼은 잠시 숨기되, 열린 메타데이터는 새 크기에 맞춰 오른쪽에 계속 표시한다. 드래그가 끝나면 기존 고정 상태로 돌아온다. 단순히 창을 이동할 때는 숨기지 않는다.
- 조작부가 표시된 상태에서 연속으로 창 크기가 바뀌어도, Windows가 버튼이 있던 영역을 다시 그리도록 하고 이미지와 자식 컨트롤을 같은 프레임으로 합성한다. 회귀 검사에서 연속 확대 후 이전 버튼 위치에 화면 픽셀이 남지 않는지 확인한다.
- 실제 마우스 드래그는 `DefWindowProcW` 안의 중첩 메시지 루프를 사용한다. 기본 처리로 넘기기 전에 앱 상태의 차용을 해제해 `WM_SIZING`과 `WM_PAINT`가 처리되도록 한다. 크기 변경 API만 호출하는 테스트와 달리, 실제 창 가장자리를 마우스로 드래그해 이전 버튼의 픽셀이 남는지 검사했다.

## 검증

- Windows 실제 실행에서 주소 대화상자의 입력 반환, 정지 이미지의 애니메이션 조작부 숨김, GIF의 조작부·프레임 제목, 크기 변경 및 메타데이터 회귀를 확인했다. 왼쪽 위와 오른쪽 아래 모서리를 각각 마우스로 연속 조작해 잔상 제거와 열린 메타데이터의 오른쪽 정렬도 확인했다.
- GTK4는 WSLg Wayland에서 우클릭에 사용하는 메뉴 표시, `ⓘ`/`Tab` 메타데이터, GIF 재생·이동·배속·제목을 자동 검사했다. 실제 Linux 데스크톱에서 마우스로 조작하거나 화면을 육안 비교하지는 않았다.

## Linux 릴리스 전 확인

아래는 **확인된 결함 목록이 아니라 미검증 영역**이다. WSLg에서는 GTK 4.14.5와 Cairo 경로의 일부 기능만 확인했다. 실제 Linux의 Wayland와 X11에서 아래를 확인한 뒤 릴리스 빌드·배포 여부를 결정한다.

| 위험 지점 | 통과 기준 |
|---|---|
| 서리 유리 렌더링·성능 | 배포 기본 Cairo와 기본 GPU 렌더러 환경을 구분해 확인한다. 좁은 창·최대화·고해상도에서 이미지 조각이나 이전 패널 잔상이 남지 않는다. 창 드래그 후 부드러운 효과가 복원되며 GIF 재생·빠른 페이지 이동이 눈에 띄게 끊기지 않는다. |
| 배치·DPI·테마 | 100%와 HiDPI/분수 배율, 밝은·어두운 테마에서 세 조작부와 오른쪽 `ⓘ`가 잘리거나 겹치지 않는다. 실제 데스크톱 지원 여부에 맞춰 다중 모니터 이동과 전체 화면에서도 확인한다. 아이콘과 메타데이터 글자가 읽히며, 긴 제목의 OS별 말줄임을 확인한다. |
| 마우스·메뉴·키보드 | 모서리를 실제 마우스로 드래그하며 패널 표시, 오른쪽 정렬, 메타데이터 스크롤을 확인한다. 우클릭·`Shift+F10` 메뉴, 파일/폴더/주소 대화상자, `Esc` 닫기와 포커스 복귀를 확인한다. 고정이 풀린 바의 가장자리 표시와 바 위에서의 포인터 유지를 검증한다. |
| 정지/애니메이션 전환·메타데이터 | PNG/CBZ와 GIF/WebP/APNG 사이를 오가며 프레임 조작부·창 제목이 남거나 깜빡이지 않는지 확인한다. 메타데이터가 있는 페이지에서 없는 페이지로 옮겼을 때 이전 정보가 사라지고, 열린 패널을 둔 채 창을 조절해도 상태가 유지된다. |
| 접근성·패키지 환경 | 키보드 포커스, 기호 버튼의 보조 이름·툴팁, 스크린리더와 텍스트 입력을 확인한다. 실제 Linux 소스 검증이 끝난 뒤 별도 승인 시 AppImage를 만들고 깨끗한 환경에서 다시 검사한다. 이번 소스 푸시는 그 패키지 검사를 대신하지 않는다. |

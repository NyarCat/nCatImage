# nCatImage

**가볍게 열고, 빠르게 넘기는 Rust 기반 로컬 코믹뷰어.**

폴더와 ZIP/CBZ를 바로 열어 이미지를 감상하는 Linux용 뷰어입니다. 로컬 파일과 OS가 연결하는 SMB·FTP·SFTP 네트워크 폴더를 읽을 수 있습니다. 감상 중 원본을 수정하지 않으며, 명시적인 `Del` 조작으로만 일반 이미지 파일을 휴지통으로 보낼 수 있습니다. 자동 원격 분석이나 감상 기록 저장 없이 동작합니다.

> **v0.6.3 개발 프리뷰** — Linux x64 AppImage와 미서명 Windows x64 `UNTESTED` 단일 EXE. Windows 네이티브 검증과 정식 제품 배포는 미완료입니다.

**이 프로젝트는 OpenCode 코딩 에이전트(Coding Agent)를 통한 AI 기반 개발 프로젝트입니다.** 설계·구현·테스트·문서에 AI가 생성하거나 수정한 내용이 포함되어 있습니다. 자동 검사 통과가 안전성·정확성·성능을 보장하는 것은 아니며, 실제 검증 범위와 남은 제한을 공개합니다.

### v0.6.3 변경 사항

- 페이지 번호 칸의 중복 `+`·`−`를 없앴습니다. 번호를 입력한 뒤 `Enter` 또는 오른쪽 `▾`로 바로 이동합니다. 상단 UI를 숨기면 `ⓘ`도 함께 숨겨지며, 이미 열린 메타데이터 패널은 그대로 유지됩니다.
- `Del`은 확인 후 현재 일반 이미지를 OS 휴지통으로 보냅니다. **다시 묻지 않기**는 삭제를 확인한 경우에만 현재 실행 동안 적용됩니다. ZIP/CBZ 내부 이미지에는 경고만 표시하며, 휴지통을 사용할 수 없으면 영구 삭제하지 않습니다.

### v0.6.2 변경 사항

- 오른쪽 아래 확대·축소 버튼 왼쪽에 현재 배율과 이미지의 표시 크기를 표시합니다. 메타데이터 패널의 복사 버튼은 내용을 일반 텍스트로 복사합니다.
- 첫 이미지에 맞춰 필요할 때만 창을 키우고, 평상시에는 여유가 있는 축을 가운데 정렬하며 창을 줄여도 배율을 유지합니다. 마지막 일반 창 크기는 다음 실행에 복원합니다.
- Linux는 Wayland 분수 배율을 그대로 사용하고, Windows는 모니터별 DPI 인식으로 OS의 창 전체 확대를 방지합니다.
- 우클릭 메뉴의 **로그 보기**에서 최근 진단 기록을 볼 수 있으며 로그 파일은 저장하지 않습니다.

### v0.6.0 변경 사항

- 페이지를 읽는 중에는 기존 이미지를 유지하고 추가 이동 입력을 무시합니다. 오류가 나면 자동으로 건너뛰지 않으며 다음 입력으로 다시 이동할 수 있습니다.
- 서리 유리 조작부를 상단·왼쪽 아래·오른쪽 아래에 배치하고 메타데이터 패널을 오른쪽 위로 옮겼습니다. 우클릭으로 파일·폴더·주소 열기 메뉴를, `[`/`]`로 같은 위치의 이전·다음 책을 열 수 있습니다.
- Linux 데스크톱 회귀 테스트를 새 창 제목과 오버레이 동작에 맞췄으며 Breeze 계열의 스크롤바 크기 경고를 수정했습니다.

### v0.5.5 변경 사항

- ImageViewer를 참고한 상·하단 플로팅 바를 GTK4와 Win32에 독립 구현했습니다. 개별 고정, 가장자리 자동 표시, 전체 화면 동작을 맞췄고 기존 Tab 메타데이터 기능은 유지했습니다.
- Windows에서 창 크기 변경 중 버튼과 바가 어긋나거나 이전 화면 잔상이 남을 수 있는 경로를 수정했습니다. 중첩 대화상자 뒤에 이미지가 ‘읽는 중’에 머물던 문제도 수정했습니다.

### v0.5.4 변경 사항

- `Tab`/`Shift+Tab`은 UI 포커스 이동 대신 **메타데이터 floating layer**를 켜고 끕니다. 기본값은 꺼짐이며, 포함된 메타데이터가 있을 때만 이미지 영역 왼쪽 위에 표시합니다.
- PNG 텍스트/생성 정보·EXIF·XMP·JPEG/GIF 코멘트를 worker에서 읽고, 원본/로그에 별도 저장하지 않습니다. GUI/worker wire v5를 같은 빌드로 사용하세요.
- 자세한 표시 범위·안전 상한·검증은 [메타데이터 레이어](doc/12-metadata-overlay.md)를 참고하세요.

### v0.5.3 변경 사항

- Windows 창 크기 변경·최대화/복원·전체 화면·UI 숨김/표시에서 재그리기와 새 크기 렌더 요청을 놓치는 경로를 수정했습니다.
- 빈 창 resize/paint 회귀를 추가했습니다. Windows DACL 오류나 실사용 미검증 상태를 해결한 것은 아닙니다.

### v0.5.2 변경 사항

- Windows x86_64 단일 EXE 실험판을 포함합니다. 정상적인 이미지 표시·보안·입력은 native Windows에서 검증하지 않았습니다.
- Win32 뷰어/공통 backend·동일 EXE worker와 파일/Job 보호를 연결했습니다. Wine에서는 Job 제한 검증 실패로 이미지 디코딩을 거부하며 보호를 우회하지 않습니다.
- Linux GTK 기능은 유지합니다. GUI/worker wire v4를 함께 배포하며 서로 다른 버전을 섞지 않습니다.

### v0.5.1 변경 사항

- 프레임마다 이전/다음 버튼을 껐다 켜던 처리를 제거해 깜빡임을 수정했습니다. 프레임 정보도 타이틀바가 아닌 애니메이션 툴바의 같은 줄에 표시합니다.
- 일시정지 상태에서 **프레임 번호 입력 → 이동 버튼 또는 Enter**로 원하는 프레임에 이동합니다. 번호는 1부터 시작하며, 전체 수를 아직 모를 때 끝을 넘으면 마지막 프레임으로 이동합니다.
- wire v3에 확인된 전체 프레임 수를 전달하고, 버튼 상태 안정성·프레임 이동 회귀를 추가했습니다.

### v0.5.0 변경 사항

- GIF/AGIF·WebP·APNG 자동 재생을 추가했습니다. 폴더와 ZIP/CBZ 내부 이미지도 지원합니다.
- 타이틀바에 프레임·재생 상태·배속을 표시하고, 이전(`,`)/다음(`.`)/재생·일시정지(`/`) 버튼과 0.25×~4× 속도 선택을 추가했습니다.
- 공통 읽기/GUI 정책·GTK 화면·OS 서비스를 분리하고 OS별 패키징 파이프라인을 준비했습니다. Windows/macOS 앱 배포 완료를 뜻하지 않습니다.
- Rust 회귀 80개와 GTK 재생/컨트롤 검사 8개를 확인했습니다. 전체 코덱·보안·성능 인증은 아닙니다.

기존 0.4.3의 기능도 유지합니다:

- SMB·FTP·SFTP URI를 KIOFuse 또는 GVfs/FUSE를 통해 연결합니다. 네트워크 버튼·`Ctrl+L`·드롭·대화상자·명령행에서 사용할 수 있습니다.
- 연결 대기를 비동기로 처리하고 이전 요청 취소·오래된 결과 거부·60초 대기 제한을 추가했습니다. 비밀번호 포함 URI는 거부하며 인증은 OS 도구에 맡깁니다.
- 드롭 형식 협상·수신·열기·표시와 네트워크 연결 결과를 경로·서버·계정 없이 기록합니다.
- FUSE 최초 읽기 중 속성 갱신에 따른 변경 오인을, 표시 전 새 열기 1회 재시도로 보완했습니다. 기존 리비전 검사는 유지합니다.
- 개발 문서·worker 통합 테스트·검증 도구·Linux CI를 저장소에 포함했습니다.

## 다운로드 및 실행

[**v0.6.3 다운로드 — Linux AppImage · Windows UNTESTED EXE**](https://github.com/NyarCat/nCatImage/releases/tag/v0.6.3)

Windows는 `nCatImage-0.6.3-UNTESTED-windows-x86_64.exe`입니다. 모니터별 DPI 인식을 지원하는 Windows 10(1703 이상)·11용 미서명 프리뷰입니다. 네이티브 CI의 `private owner/DACL required` 오류는 해결되지 않았습니다.

GTK와 이미지 처리 worker를 포함한 **AppImage 파일 하나**로 배포합니다. Rust나 GTK 개발 패키지를 따로 설치할 필요가 없습니다.

```bash
chmod +x nCatImage-0.6.3-x86_64.AppImage
./nCatImage-0.6.3-x86_64.AppImage
./nCatImage-0.6.3-x86_64.AppImage /path/to/book.cbz
```

- 대상: **Linux x86_64, glibc 2.39 이상**(Ubuntu 24.04 및 동급 이상 환경).
- X11 또는 Wayland 그래픽 세션과 시스템 그래픽·폰트 환경이 필요합니다. Windows/macOS, ARM64, musl 기반 Alpine은 지원 대상이 아닙니다.
- 호환성을 위해 배포본은 기본적으로 Cairo 소프트웨어 렌더러를 사용합니다. `GSK_RENDERER`를 지정하면 변경할 수 있습니다.
- 모든 배포판·GPU·입력기 조합에서 검증된 것은 아닙니다. AppImage가 모든 Linux에서 실행된다는 뜻은 아닙니다.
- 외부 fcitx/IBus 모듈은 포함하지 않습니다. 시스템 입력기 설정에 따라 경고나 한글 입력 문제가 있을 수 있으며 별도 검증이 필요합니다.

FUSE 관련 오류가 나면 설치 없이 압축 해제 실행을 시도하세요:

```bash
./nCatImage-0.6.3-x86_64.AppImage --appimage-extract-and-run
```

다운로드 파일의 무결성은 릴리스에 함께 제공하는 `SHA256SUMS`로 확인할 수 있습니다:

```bash
sha256sum -c SHA256SUMS
```

## 주요 기능

- 이미지 파일, 폴더, ZIP/CBZ 열기와 파일 드래그 앤 드롭
- OS 연결 도구를 통한 SMB·FTP·SFTP 파일/폴더 열기
- 자연 정렬, 이전/다음 페이지 및 페이지 번호 이동
- JPEG, PNG, BMP, WebP, GIF 표시
- **GIF/AGIF·애니메이션 WebP·APNG 자동 재생**, 폴더·ZIP/CBZ에서도 동일하게 동작
- EXIF 방향 적용, 임시 회전, 맞춤, 확대, 스크롤·드래그 패닝, 전체 화면
- 좌우 읽기 방향 전환
- 별도 worker 프로세스에서 이미지 처리, 오래된 요청 취소
- 바이트 제한 페이지 캐시와 인접 페이지 미리 읽기

### 현재 제한

RAR/CBR·7Z, 두 장 보기 UI, 이어보기, 썸네일, ICC 색관리는 아직 지원하지 않습니다. 폴더는 하위 폴더를 탐색하지 않습니다.

애니메이션은 worker가 프레임을 순차 디코딩하고 파일의 지연 시간·반복 횟수에 따라 재생합니다. 프레임 전체를 메모리에 적재하지 않으며, 페이지 이동·회전·종료 시 이전 재생을 취소합니다. 프레임 지연은 원본 기준 10ms~60초, 한 재생 주기는 최대 10,000프레임으로 제한합니다. 이 기능은 v0.5.0부터 포함되며 과거 v0.4.3 배포본에는 없습니다.

현재/전체 프레임은 창 제목에, 배속과 재생 버튼은 왼쪽 아래에 표시합니다. 전체 수는 첫 반복·재생 종료·범위를 넘는 번호 이동 후 확인되며 그전에는 `?`로 표시합니다.

| 애니메이션 조작 | 단축키 |
|---|---|
| 이전 프레임 (일시정지) | `,` |
| 다음 프레임 (일시정지) | `.` |
| 재생 / 일시정지 (종료 후에는 처음부터 재생) | `/` |
| 재생 속도 | UI의 **0.25×~4×** 선택 |
| 지정 프레임 이동 (일시정지 중) | 프레임 번호 입력 후 **이동 / Enter** |

프레임 컨트롤은 정지 이미지에서는 숨겨집니다. 애니메이션에서는 이전/다음 버튼을 매 프레임 비활성화하지 않고 유지하며 첫 프레임 이전으로는 이동하지 않습니다. 이전/번호 이동은 worker가 처음부터 다시 합성하므로 긴 애니메이션에서는 느릴 수 있고, 디코딩 중에는 중복 프레임 이동을 받지 않습니다. 일시정지 직전에 요청한 프레임은 한 번 더 도착할 수 있습니다.

현재 출력은 **최대 8MiB 미리보기**이며 원본 해상도·4K 최종 화질을 보장하지 않습니다. 큰 이미지는 메모리 제한으로 거부될 수 있습니다. 기본 이미지 처리 예약 예산은 GUI와 worker 합산 192MiB이며, 앱 전체 RSS 제한과는 다릅니다.

## 단축키

Linux와 Windows는 [ImageViewer](https://github.com/edith2580/ImageViewer)의 상·하단 플로팅 바, 가장자리 자동 표시, 개별 고정 방식에서 UI 아이디어를 가져왔습니다. 원본 코드와 아이콘을 복사하지 않고 기존 GTK4·Win32 위에 각각 구현했습니다.

플로팅 바와 메타데이터는 [서리 유리 스타일](doc/13-frosted-reader-ui.md)로 표시합니다. 패널 뒤 이미지에만 약한 흐림을 적용하며, 조작 버튼은 기호를 우선 쓰고 의미가 불분명한 곳에는 짧은 라벨을 남깁니다.

페이지 이동은 **상단 중앙**, 애니메이션 조작은 **왼쪽 아래**(움직이는 이미지에서만), 확대·축소는 **오른쪽 아래**에 있습니다. 이미지 영역을 우클릭하면 파일·폴더·주소를 열 수 있습니다. 이미지 상태와 현재/전체 프레임 수는 창 제목에 표시합니다. 상·하단의 고정은 처음에 켜져 있으며 백틱(<kbd>&#96;</kbd>)으로 함께 전환할 수 있습니다. [자세한 배치](doc/14-reader-control-layout.md)

개발 소스의 기본 보기는 원본 크기를 유지하며, 창에 여유가 있는 방향으로 이미지를 가운데에 배치합니다. 시작할 때 받은 첫 이미지에만 필요하면 창을 늘립니다. 이미지를 담기엔 좁은 방향은 왼쪽·위를 기준으로 오른쪽·아래가 가려집니다. 전체를 보고 싶으면 `9`를 누르면 됩니다. 마지막 일반 창의 크기는 [OS별 상태 파일](doc/02-reader-ux.md#현재-linuxwindows-동작-첫-이미지와-창-크기)에 저장됩니다.

| 동작 | 키 |
|---|---|
| 파일 / 폴더 열기 | `Ctrl+O` / `Ctrl+Shift+O` |
| 네트워크 주소 열기 | `Ctrl+L` 또는 우클릭 → **주소 열기** |
| 다음 / 이전 페이지 | `↓`, `Space`, `PageDown` / `↑`, `Backspace`, `PageUp` |
| 이전 / 다음 폴더·ZIP(CBZ) | `[` / `]` |
| 읽기 방향에 따른 페이지 이동 | `←` / `→` |
| 읽기 방향 전환 | `D` |
| 확대 / 축소 / 맞춤 | `+` / `-` / `9` |
| 회전 / 반대 회전 | `R` / `Shift+R` |
| 다시 열기 | `F5` |
| 상·하단 바 고정 일괄 전환 | 백틱(<kbd>&#96;</kbd>) |
| 전체 화면 전환 | `F11` |
| 종료 | `Esc` / `Ctrl+Q` |

`[`와 `]`는 같은 부모 폴더에서 **지원 이미지가 바로 들어 있는 폴더**와 `.zip`/`.cbz` 파일을 이름순으로 함께 탐색합니다(`2` 다음 `10`). 이미지 파일을 직접 열었다면 그 이미지가 들어 있는 폴더를 기준으로 이동합니다. 하위 폴더는 재귀 탐색하지 않으며, 처음과 끝에서 순환하지 않습니다. 책 이동 방향은 좌우 읽기 방향과 별개입니다.

페이지 번호 등 UI의 키보드 조작은 **해당 컨트롤을 직접 클릭했을 때** 활성화됩니다. 오른쪽 위 `ⓘ` 또는 `Tab`/`Shift+Tab`으로 **메타데이터 레이어를 켜고 끕니다(기본 꺼짐)**. 현재 이미지에 메타데이터가 있을 때만 오른쪽에 표시하며, 전체 화면과 창 크기 변경 중에도 사용할 수 있습니다. PNG 텍스트/생성 정보·EXIF·XMP·JPEG/GIF 코멘트를 읽고, 없는 페이지에서는 이전 내용을 숨깁니다. 긴 내용은 스크롤하며 항목 수/값 길이에는 안전 상한이 있습니다. UI를 클릭한 뒤에는 Tab을 제외한 입력 위젯의 기본 키 동작을 사용하고, 이미지 영역을 클릭하면 페이지 단축키 모드로 돌아갑니다. `↑`/`↓`는 좌우 읽기 방향과 관계없이 이전/다음 페이지로 이동합니다. 메인 뷰어의 `Esc`는 전체화면 해제가 아니라 **앱 종료**이며, 페이지 번호 입력 중에도 적용됩니다. 별도 파일 선택·네트워크 주소 입력 창의 표준 입력은 유지합니다.

## 네트워크 폴더: Samba / FTP / SFTP

우클릭 → **주소 열기** 또는 `Ctrl+L`에서 주소를 입력하거나, 파일 관리자에서 파일/폴더 **한 개**를 드롭하세요. 파일/폴더 열기 대화상자와 명령행의 네트워크 URI도 같은 연결 경로를 사용합니다.

```bash
./nCatImage-0.5.0-x86_64.AppImage 'smb://server/share/comics/'
./nCatImage-0.5.0-x86_64.AppImage 'ftp://server/comics/book.cbz'
./nCatImage-0.5.0-x86_64.AppImage 'sftp://user@server/comics/'
```

- **KDE:** 세션의 **KIOFuse**와 해당 프로토콜의 KIO worker를 사용해 로컬 접근 경로를 얻습니다. Debian/Ubuntu 계열은 `kio-fuse kio-extras`, Arch 계열은 `kio-fuse kio-extras` 패키지를 확인하세요.
- **GNOME/GVfs:** KIOFuse가 없으면 GIO의 원격 백엔드와 GVfs/FUSE 연결을 시도합니다. Debian/Ubuntu에서는 `gvfs-backends gvfs-fuse`가 필요합니다. AppImage와 시스템 GIO 모듈의 호환성에 따라 이 경로를 사용할 수 없을 수 있습니다.
- **OS에서 이미 마운트한 경로**(`/mnt/...`, CIFS, sshfs 등)는 기존 로컬 경로와 동일하게 읽습니다. 연결 도구가 없으면 앱에 표시되는 안내에 따라 OS에서 먼저 마운트하세요. 데스크톱 연결 도구는 AppImage에 포함하지 않습니다.
- 인증은 OS 연결 도구가 처리합니다. 먼저 파일 관리자에서 접속·로그인하면 편리합니다. 앱은 서버·계정·비밀번호를 설정 파일이나 로그에 저장하지 않으며, **비밀번호가 포함된 URL은 거부**합니다. OS 도구가 보관하는 자격증명은 해당 도구의 설정을 따릅니다.
- **FTP는 암호화되지 않습니다.** 민감한 자료에는 SFTP 또는 안전하게 설정한 SMB를 권장합니다. HTTP·WebDAV·FTPS 등 다른 URI는 이번 범위가 아닙니다.
- 연결 요청은 비동기로 처리하고 앱의 결과 대기를 최대 60초로 제한합니다. 다른 항목을 열거나 종료하면 이전 연결 결과가 화면을 덮어쓰지 않습니다. OS 도구 쪽의 연결·마운트 수명은 해당 도구의 정책을 따릅니다. 해석·디코딩·압축 읽기는 기존 worker에서 수행합니다.
- 앱에서 책 전체를 별도 다운로드하는 경로는 추가하지 않았습니다. 다만 KIO/GVfs가 탐색·랜덤 읽기를 위해 **네트워크 데이터나 파일 전체를 OS 캐시에 저장할 수 있으며**, 해당 데몬의 캐시는 앱의 192MiB 예약 예산에 포함되지 않습니다. 로컬 파일과 같은 속도를 보장하지 않으며, 느린 서버·연결 끊김에 따라 기존 worker 제한 시간에 걸릴 수 있습니다.

## 소스 빌드

### Windows 단일 EXE 개발 상태

Windows는 GTK DLL이나 worker EXE를 추출하지 않는 **단일 native EXE**로 개발합니다. [개발 상태·재현 방법](doc/11-windows-single-exe-wine.md)에 따라 파일 서비스·Job 보호·같은 EXE worker와 Win32 뷰어 기능을 연결했습니다. Wine에서는 Job 제한 readback이 실패해 보호된 디코딩을 거부하며, native Windows 이미지 표시·보안·입력 동등성은 아직 검증 전입니다. v0.5.2에는 사용자 승인으로 **UNTESTED 실험판**을 공개하며 정식 Windows readiness는 false입니다.

### Linux

현재 소스는 Windows/macOS 포팅 준비를 위해 **공통 읽기/GUI 정책 → GTK frontend → Linux 서비스**로 분리되어 있습니다. OS별 재사용 범위와 남은 구현은 [포팅 경계](doc/09-portability.md)를 참고하세요. Windows/macOS 앱 지원이 추가된 것은 아닙니다.

OS별 배포 파이프라인은 [배포 문서](doc/10-distribution.md)를 따릅니다. Linux는 AppImage, Windows는 native 단일 EXE, macOS는 `.app` 포함 DMG를 목표로 합니다. 기존 Windows GTK ZIP 경로는 비활성화했습니다. **Windows/macOS 제품 배포는 포팅 미완료 사전 검사에서 차단됩니다.** Windows 개발 artifact와 제품 배포는 구분합니다. 새 태그의 세 OS 검증이 모두 성공한 경우에만 자동 초안 릴리스를 만듭니다.

저장소의 `rust-toolchain.toml`에 지정된 Rust와 GTK **4.10 이상** 개발 패키지가 필요합니다. Ubuntu 24.04에서는 다음과 같이 빌드합니다:

```bash
sudo apt install build-essential pkg-config libgtk-4-dev
cargo build --workspace --release --locked
./target/release/ncat-linux /path/to/book.cbz
```

`ncat-linux`와 `ncat-worker`는 같은 디렉터리에 두세요. GUI만 빌드하면 worker가 누락될 수 있으므로 workspace 전체를 빌드해야 합니다.

AppImage 생성 방법과 필요한 추가 패키지는 [`packaging/linux/build-appimage.sh`](packaging/linux/build-appimage.sh)에 있습니다. 배포용 빌드는 최신 개발 머신이 아닌 Ubuntu 24.04 기준 환경에서 만드세요.

## 실행 설정 및 오류 보고

| 환경변수 | 기본값 | 설명 |
|---|---:|---|
| `NCAT_MEMORY_MIB` | 192 | 이미지 관련 예약 예산, 1~384MiB |
| `NCAT_CACHE_MIB` | 총 예산의 1/8 | 캐시 상한, 0이면 비활성화, 최대 총 예산의 1/3 |
| `NCAT_WORKSPACE_MIB` | 128 | 작업 공간 상한, 8~384MiB, 총 예산으로 추가 제한 |
| `NCAT_TIMEOUT_SECS` | 15 | 작업 제한 시간, 1~120초 |
| `NCAT_PREFETCH` | 1 | 인접 페이지 미리 읽기, 0/1 또는 false/true |

v0.6.1부터 Linux·Windows에서 **우클릭 → 로그 보기**를 열면 현재 실행의 최근 진단 기록(최대 128줄)을 확인하고 복사할 수 있습니다. 로그를 파일로 저장하지 않으며 앱을 종료하면 기록이 사라집니다. 이전 버전이 저장한 파일은 건드리지 않습니다.

Linux에서는 드롭 수신·형식 협상·열기 결과와 네트워크 연결 단계를 확인할 수 있습니다. `Ready` 뒤에 `Entered`가 없으면 드롭이 앱에 도착하지 않은 경우이고, `OpenQueued` 뒤에 `OpenFailed`가 있으면 열기 또는 디코딩 단계의 오류입니다. 두 플랫폼 모두 워커 오류 등을 기록하되 경로·파일명·URI·서버·계정·비밀번호·이미지 내용은 남기지 않습니다. 진단 기록은 외부로 전송하지 않습니다.

## 개발 상태

Linux x86_64부터 개발 중인 개인 프로젝트입니다. 정식 코덱 호환성·보안·성능 검증이 완료된 제품이 아니며, 다른 뷰어보다 가볍다는 비교 결과를 주장하지 않습니다. 코드 라이선스는 아직 미정입니다. 배포본에 포함된 외부 구성요소의 라이선스 고지는 AppImage 내부 `usr/share/doc/ncatimage/`에 있습니다.
